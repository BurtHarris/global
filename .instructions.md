# Workspace-wide developer instructions

## Default toolchain policy

- Use `mise` as the default tool manager for installs, upgrades, versions, and project-local task execution.
- Prefer `mise`-managed runtimes and CLIs over manual installs or shell-specific wrappers.
- Add or update `mise.toml` tasks instead of expanding custom install scripts when the work is meant to be reused by coding agents.

## Reusable script guidance

- Build reusable scripts and project commands around `mise` so they are discoverable, portable, and consistent across machines.
- Keep scripts minimal and declarative; they should coordinate `mise` tasks rather than embedding tool paths or per-machine assumptions.
- When a project needs build/test/run commands, prefer `mise run <task>` and related task definitions over large package.json script pages.

## Agent workflow expectation

- Coding agents should prefer `mise` for provisioning, tool management, and project automation unless a task specifically requires a system dependency outside `mise`'s scope.
- If a new automation path is needed, prefer a `mise` task or a thin wrapper that calls a `mise` task rather than adding a bespoke setup script.
